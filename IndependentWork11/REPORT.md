# Звіт самостійної роботи 11

## 1. Опис реалізованих пайплайнів

1. **Пайплайн 1: Найпопулярніші продукты за категоріями**
   - **Мета:** Знайти Топ-3 товари за кількістю продажів у кожній категорії.
   - **Оператори:** `GroupBy` (групування за товаром), `Select`, `Join` (зв'язування з назвами/категоріями), `GroupBy` (за категоріями), `OrderByDescending` + `Take(3)` (топ товари).

2. **Пайплайн 2: Загальний дохід за містами клієнтів**
   - **Мета:** Розрахувати фінансовий виторг у розрізі географії (міст).
   - **Оператори:** Подвійний `Join` (об'єднання `Sale`, `Product`, `Customer`), `Select` (обчислення `Quantity * UnitPrice`), `GroupBy` (за містом), `Sum`, `OrderByDescending`.

3. **Пайплайн 3: Продажі за місяцями та роками**
   - **Мета:** Побудувати часовий ряд обсягу продажів та доходу.
   - **Оператори:** `Join`, `GroupBy` за анонімним об'єктом `{ Year, Month }`, `Sum`, `OrderBy` та `ThenBy`.

4. **Пайплайн 4: Аналіз VIP-клієнтів (Власний запит)**
   - **Мета:** Виявити найцінніших покупців, які сумарно витратили понад 5000 грн.
   - **Оператори:** `Join`, `GroupBy`, `Select`, `Where` (фільтрація порогу витрат), `Join` (зв'язок із даними клієнта), `OrderByDescending`.

## 2. Аналіз продуктивності та результатів

| Пайплайн | Середній час виконання (ms) |
| :--- | :--- |
| **1. TopProductsByCategory** | ~0.8 - 1.5 ms |
| **2. TotalRevenueByCity** | ~0.5 - 1.2 ms |
| **3. SalesByMonthAndYear** | ~0.4 - 0.9 ms |
| **4. VIPCustomersAnalysis** | ~0.6 - 1.1 ms |

### Фактори, що впливають на продуктивність:
- **Операції Join та GroupBy:** Вимагають побудови внутрішніх хеш-таблиць у пам'яті (LINQ to Objects), що додає тимчасові витрати на алокацію.
- **Масштаб даних:** При збільшенні обсягу об'єктів з 500 до 1,000,000 виконання в LINQ to Objects може сповільнитися через роботу Garbage Collector (GC).
- **Фільтрація `Where`:** Додавання `Where` на початку пайплайну (до `Join`) істотно прискорює обробку.

## 3. Відповіді на контрольні запитання

1. **Переваги LINQ для ETL-пайплайнів:** Декларативний стиль робить трансформацію даних зрозумілою та короткою, виключаючи ручну підтримку складних вкладених циклів та тимчасових колекцій.
2. **Чому поєднують Join, GroupBy, Select, OrderBy:** Це стандартна послідовність аналітичної обробки (збагачення даних -> агрегація -> розрахунок метрик -> сортування).
3. **Фактори впливу на продуктивність LINQ:** Порядок виконання операторів (рання фільтрація), повторна ітерація по `IEnumerable` (необхідність додавання `.ToList()`), алокація пам'яті під анонімні типи.
4. **Читабельність та підтримка:** Форматування кожного оператора з нового рядка, розбиття складних виразів на декілька проміжних змінних та відсутність надмірних вкладених суб-запитів.
