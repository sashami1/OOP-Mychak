  •Лабораторна робота No4
  
• Тема: Наслідування. Ключові слова base, override, virtual. Приховування членів (new).

• Мета:Навчитися створювати ієрархії класів, використовувати ключові слова base, virtual, override
для реалізації поліморфізму, а також розуміти відмінності між override та приховуванням членів
за допомогою new.

• Висновок

Під час виконання лабораторної роботи я на практиці опанувала механізми успадкування та поліморфізму, створивши ієрархію класів Document, TextDocument та ImageDocument. Навчилася застосовувати ключове слово base для виклику конструкторів базового класу, а також дослідила відмінність між перевизначенням методів (virtual/override) та їхнім приховуванням (new). Завдяки контрольному запуску було підтверджено, що override забезпечує динамічне зв'язування залежно від фактичного типу об'єкта в пам'яті, тоді як new реалізує статичне зв'язування, де метод обирається за типом посилання.

 • Контрольні запитання
 •1. Принцип наслідування та приклад з життя
   
Наслідування дозволяє створити новий клас на основі вже існуючого, щоб не писати однаковий код двічі. Похідний клас бере всі властивості базового та додає свої.

Приклад: Базовий клас «Транспорт» має параметр швидкість. Його похідні класи «Автомобіль» та «Велосипед» забирають себе цю швидкість, але Автомобіль додатково має об'єм двигуна, а Велосипед — кількість передач.

•2. Для чого потрібне ключове слово base?
Воно використовується в похідному класі, щоб звернутися до «батьківського» (базового) класу. Зазвичай потрібне для двох речей:

Передати дані в конструктор базового класу при створенні об'єкта.

Викликати початкову версію методу з базового класу перед тим, як додати власну логіку.

•3. Різниця між virtual та override

virtual каже: «Цей метод у базовому класі можна змінити в похідних».

override каже: «Я змінюю цей метод і отримую нову версію для похідного класу».

Завдяки їм працює поліморфізм: якщо ми збережемо різні об'єкти в один список базового типу, програма при виклику методу сама зрозуміє, чий саме override-метод треба запустити (в залежності від того, що це за об'єкт у пам'яті).

•4. Навіщо потрібен модифікатор new та які наслідки?
Модифікатор new використовують, коли треба створити метод з таким самим ім'ям, як у базовому класі, але без повноцінного перевизначення (наприклад, якщо метод у базовому класі не мав virtual).

Наслідки:
Поліморфізм зникає.

Яка версія методу спрацює, залежить не від самого об'єкта, а від того, як ми до нього звертаємося: через тип похідного класу — спрацює новий метод, а якщо привести його до базового типу — спрацює старий метод базового класу.
