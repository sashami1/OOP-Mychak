# Звіт з Самостійної роботи №9: Делегати й лямбда-вирази

## 1. Відповіді на ключові питання

### Чому делегати корисні для створення таких утиліт?
Делегати передають поведінку (код або функцію) як параметр у метод. Це дозволяє відокремити алгоритм обходу колекції від конкретної логіки обробки елементів. Наприклад, один метод `Filter` може фільтрувати як числа, так і складні об'єкти за довільними критеріями.

### Як лямбда-вирази спрощують виклик цих методів?
Лямбда-вирази (`x => x.Price > 1000`) дають можливість писати анонімні функції лаконічно прямо в місці виклику, без необхідності попередньо оголошувати окремі методи або класи-обробники.

### Порівняння власних методів із вбудованими LINQ-операторами

| Власний метод у `CollectionUtils` | Аналог у LINQ | Опис |
| :--- | :--- | :--- |
| `Map<TSource, TResult>` | `.Select()` | Трансформує кожен елемент колекції |
| `Filter<T>` | `.Where()` | Фільтрує елементи за умовою (предикатом) |
| `MaxBy<T, TKey>` | `.MaxBy()` | Знаходить об'єкт з максимальним значенням ключа |
| `ForEach<T>` | `.ToList().ForEach()` | Виконує дію над кожним елементом |

## 2. Відповіді на контрольні запитання

1. **Чому делегати є зручним механізмом для передавання поведінки в узагальнені методи?**
   Вони забезпечують строго типізоване передавання методу як аргументу, що дозволяє створювати гнучкі та універсальні алгоритми без прив'язки до конкретних типів даних.

2. **У чому різниця між `Func<T, TResult>`, `Action<T>` та `Predicate<T>`?**
   - `Func<T, TResult>` приймає аргумент типу `T` та повертає значення типу `TResult`.
   - `Action<T>` приймає аргумент типу `T` та нічого не повертає (`void`).
   - `Predicate<T>` приймає аргумент типу `T` та завжди повертає логічне значення `bool`.

3. **Які переваги дає поєднання generic-методів і лямбда-виразів?**
   Це забезпечує абсолютну універсальність коду: метод працює з будь-яким типом даних (`T`), а лямбда-вираз визначає точну операцію в одному рядку без втрати продуктивності та типобезпеки.

4. **У яких випадках власні утиліти корисно реалізувати самостійно?**
   - Для роботи на застарілих версіях .NET або обмежених середовищах без LINQ.
   - Для створення кастомних оптимізованих алгоритмів або специфічного логування під час обходу даних.
   - Для кращого розуміння внутрішнього устрою LINQ та функціонального програмування в C#.
