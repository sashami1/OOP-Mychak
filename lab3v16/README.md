Лабораторна робота No3


• Тема: Життєвий цикл об’єкта та керування ресурсами.
Мета: Поглибити розуміння життєвого циклу об’єкта в C#, навчитися працювати з некерованими
ресурсами, реалізувати інтерфейс IDisposable та патерн Dispose.

Висновок 

У ході виконання лабораторної роботи № 3 було досліджено життєвий цикл об'єктів у мові C# та засвоєно механізми керування керованими й некерованими ресурсами. На прикладі класу SensorReader (Варіант 16) реалізовано стандартний патерн Dispose шляхом імплементації інтерфейсу IDisposable, використання захищеного віртуального методу Dispose(bool disposing), деструктора ~SensorReader() та виклику GC.SuppressFinalize(this). Під час проведення експериментів у методі Main було продемонстровано та порівняно три сценарії звільнення ресурсів: автоматичне через блок using, явне через метод Dispose() та детерміновану фіналізацію збирачем сміття.

контрольні запитаня

Що таке життєвий цикл об’єкта в .NET?
Це етапи існування об'єкта в пам'яті: створення (виділення пам'яті в купі та виклик конструктора), використання (виклики методів), збирання сміття (GC виявляє відсутність посилань) та фіналізація (виклик деструктора та звільнення пам'яті).

Яка різниця між керованими та некерованими ресурсами?
Керованими повністю опікується .NET і GC (пам'ять для масивів чи об'єктів). Некеровані — це ресурси операційної системи (файли, сокети, бази даних), які потрібно закривати вручну.

Для чого призначений інтерфейс IDisposable?
Для миттєвого та ручного звільнення ресурсів об'єкта через метод Dispose(), не чекаючи автоматичного спрацювання збирача сміття.

Як оператор using допомагає в керуванні ресурсами?
Він гарантує автоматичний виклик Dispose() при виході з блоку коду, навіть якщо всередині виникла помилка (працює як try-finally).

Навіщо в патерні Dispose використовується метод GC.SuppressFinalize()?
Він скасовує виклик деструктора для об'єкта, чиї ресурси вже звільнені через Dispose(), що прискорює очищення пам'яті.

Чому в деструкторі викликається Dispose(false), а в методі Dispose() - Dispose(true)?
Dispose(true) очищає i керовані, і некеровані ресурси за викликом розробника. Dispose(false) очищає лише некеровані ресурси, бо керовані під час роботи GC вже можуть бути знищені.
