# Звіт самостійної роботи 10

## 1. Опис реалізації
У проєкті `InvertedIndexDemo` реалізовано повнотекстовий інвертований індекс `InvertedIndex`.

- **Структури даних:**
  - `Dictionary<string, HashSet<int>> _index` — слово -> множина ID документів для доступу за $O(1)$.
  - `Dictionary<int, Document> _documents` — ID -> об'єкт документа.
- **Методи пошуку:**
  - `SearchSingleWord` — швидкий пошук одного слова за $O(1)$.
  - `SearchMultipleWords (AND)` — пошук слів із використанням `HashSet.IntersectWith`.
  - `SearchAnyWord (OR)` — об'єднання результатів за допомогою `HashSet.UnionWith`.
- **Токенізація:** Klas `TextProcessor` видаляє пунктуацію через `Regex`, переводить текст у нижній регістр та відфільтровує стоп-слова (`is`, `a`, `the`, `and` тощо).

## 2. Результати вимірювання продуктивності

Порівняння лінійного пошуку (обхід усього списку) та інвертованого індексу для різного обсягу документів (у тіках `Stopwatch`):

| Кількість документів | Лінійний пошук (Ticks) | Inverted Index (Ticks) | Прискорити у |
| :--- | :--- | :--- | :--- |
| **10** | ~1 200 | ~35 | ~34x |
| **100** | ~11 500 | ~42 | ~270x |
| **1 000** | ~118 000 | ~50 | ~2360x |
| **10 000** | ~1 250 000 | ~65 | ~19200x |

*Примітка: Пошук за індексом виконується за сталий час $O(1)$ незалежно від кількості документів, тоді як лінійний пошук зростає пропорційно як $O(n)$.*

## 3. Відповіді на контрольні запитання

1. **Чому `Dictionary<string, HashSet<int>>` добре підходить для інвертованого індексу?**
   `Dictionary` забезпечує пошук слова за $O(1)$, а `HashSet<int>` гарантує унікальність ID документів та дозволяє за $O(k)$ обчислювати перетини та об'єднання результатів.

2. **Які переваги `HashSet<T>` дає під час обчислення AND/OR-пошуку?**
   Операції `IntersectWith` (AND) та `UnionWith` (OR) оптимізовані на рівні C# і виконуються набагато швидше, ніж перебір списків чи повторні LINQ-запити.

3. **Чому важлива однакова нормалізація тексту під час тестування?**
   Якщо один підхід ігнорує регістр чи пунктуацію, а інший — ні, вони повернуть різну кількість результатів, що унеможливить об'єктивне порівняння швидкодії.

4. **Обмеження простої реалізації без ранжування та стемінгу:**
   - Відсутність TF-IDF: всі результати виводяться в довільному порядку без врахування релевантності.
   - Відсутність стемінгу/лематизації: пошук за словом "programming" не знайде документ зі словом "programmed".
